## 4. Requirements（仕様）

### OnboardingWizard.tsx
- 'use client' コンポーネント
- ステート管理: currentStep (1-4), formData: { username, avatar_type, mascot_type }
- プログレスバーを上部に表示（Step 1/3, 2/3, 3/3）
- 各ステップはアニメーション付きで遷移（CSS transition）
- immutableなstate更新（spread operator使用）

### StepName.tsx (Step 1)
- 「冒険者の名前を決めよう！」
- Inputコンポーネントでusername入力
- バリデーション: 2-30文字、英数字+ハイフン+アンダースコアのみ
- 入力時にリアルタイムバリデーション表示
- 「次へ」ボタン

### StepAvatar.tsx (Step 2)
- 「キャラクタータイプを選ぼう！」
- 3つのカードから選択:
  - planner: 「プランナー」計画を立てるのが得意 🧙‍♂️
  - explorer: 「エクスプローラー」好奇心旺盛な冒険家 ⚔️
  - crafter: 「クラフター」ものづくりの達人 🛠️
- 選択中のカードはborder-quest-primaryでハイライト
- 「次へ」「戻る」ボタン

### StepMascot.tsx (Step 3)
- 「相棒を選ぼう！」
- 2つのカードから選択:
  - cat: 「ネコ」気まぐれだけど賢い 🐱
  - dog: 「イヌ」忠実で元気いっぱい 🐶
- 選択中のカードはborder-quest-primaryでハイライト
- 「完了」「戻る」ボタン
- 「完了」押下時にServer Actionを呼び出し

### StepComplete.tsx (Step 4)
- 「冒険の準備が整いました！」
- ユーザーが選択した情報を表示（名前、アバター、マスコット）
- 「最初のクエストへ！」ボタン → /(main) へリダイレクト
- 簡単なアニメーション（scale + fade in）

### Server Action: completeOnboarding
```typescript
'use server';
// 1. Supabase auth.getUser() でユーザーID取得
// 2. onboardingSchema でバリデーション
// 3. users テーブルに INSERT (id, username, avatar_type, mascot_type, onboarding_completed: true)
// 4. エラーハンドリング（username重複時のメッセージ）
// 5. 成功時はリダイレクトしない（クライアント側で制御）
```

## 5. Constraints（制約）
- TailwindCSS 4のみ使用（CSS Modules禁止）
- Server Actions使用（API Route不可）
- Zod v4でサーバーサイドバリデーション（src/features/quest/types/schema.ts の onboardingSchema 使用）
- 型定義は src/types/index.ts の既存型を使用
- immutableパターン（state mutation禁止）
- ファイルは200-400行、最大800行
- 全コンポーネントでTailwindCSSのテーマカラー変数を使用（ハードコードされた色値禁止）
